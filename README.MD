## ✨ Особенности {#1}

- **Гибкая структура**: от 1 до 5 контестов, в каждом от 1 до 5 задач (A, B, C, D, E)
- **Автоматическая проверка решений** на 100 тестах
- **Система оценивания**: 1 балл за каждый пройденный тест
- **Режимы тестирования**:
  - *Последовательный*: остановка после первой ошибки
  - *Независимый*: выполнение всех тестов независимо
- **Кастомные чекеры** для сложных проверок вывода
- **Веб-интерфейс** с авторизацией и рейтингом
- **Docker-контейнеризация** для простого развертывания

## 🛠 Технологии {#2}

- **Backend**: Python 3.x + Flask
- **Frontend**: HTML/CSS (шаблоны Jinja2)
- **База данных**: JSON-файл (users_data.json)
- **Контейнеризация**: Docker

## 🚀 Быстрый старт {#3}

### Запуск через Docker

1. **Клонируйте репозиторий**:
   ```bash
   git clone <url-репозитория>
   cd project
   ```

2. **Соберите Docker-образ**:
   ```bash
   docker build -t tournament-platform .
   ```

3. **Запустите контейнер**:
   ```bash
   docker run -d -p 5000:5000 \
     --name tournament \
     -v $(pwd)/tasks:/app/tasks \
     -v $(pwd)/users_data.json:/app/users_data.json \
     tournament-platform
   ```

4. **Добавьте первого участника**:
   ```bash
   docker exec -it tournament python admin.py add admin password123
   ```

5. **Откройте браузер**:
   ```
   http://localhost:5000
   ```

### Полезные команды Docker

```bash
# Просмотр логов
docker logs -f tournament

# Остановка контейнера
docker stop tournament

# Запуск остановленного контейнера
docker start tournament

# Удаление контейнера
docker rm tournament

# Выполнение команд внутри контейнера
docker exec -it tournament python admin.py top
```

## ⚙️ Настройка контестов и задач {#5}

### Создание контеста

1. Создайте папку `tasks/contest1/` (обязательно с единицы)
2. Добавьте файл `config.json`:

```json
{
    "contest_name": "Введение в алгоритмы",
    "contest_info": "Первый контест для знакомства с платформой"
}
```

### Добавление задачи

1. Внутри папки контеста создайте папку `A` (обязательно с A)
2. Добавьте необходимые файлы:

#### `config.json` - настройки задачи

```json
{
    "name": "Сумма двух чисел",
    "time_limit": "1",
    "memory_limit": "256",
    "sample_in_1": "2 2",
    "sample_out_1": "4",
    "sample_in_2": "3 5",
    "sample_out_2": "8",
    "use_checker": false,
    "independent_tests": false
}
```

| Поле | Обязательное | Описание |
|------|-------------|----------|
| `name` | ✅ | Название задачи |
| `time_limit` | ✅ | Ограничение по времени (секунды) |
| `memory_limit` | ✅ | Ограничение по памяти (мегабайты) |
| `sample_in_1`, `sample_out_1` | ✅ | Пример для отображения участникам |
| `sample_in_2`, `sample_out_2` | ❌ | Второй пример (опционально) |
| `use_checker` | ❌ | Использовать кастомный чекер (по умолчанию `false`) |
| `independent_tests` | ❌ | Независимое тестирование (по умолчанию `false`) |

#### `problem.txt` - условие задачи

HTML-код с описанием задачи. Пример:
```html
<h2>Сумма двух чисел</h2>
<p>Даны два целых числа. Найдите их сумму.</p>
<h3>Формат ввода</h3>
<p>Два целых числа через пробел.</p>
<h3>Формат вывода</h3>
<p>Одно целое число - сумма.</p>
```

#### Подготовка тестов

Создайте папки `test/` и `ans/` с файлами от `1.txt` до `100.txt`:

**test/1.txt** (входные данные):
```
5 3
```

**ans/1.txt** (ожидаемый результат):
```
8
```

**Важно**: 
- Всегда должно быть ровно **100 тестов**
- Файлы нумеруются с 1
- Если задача использует чекер (`use_checker: true`), в `ans/` помещается то, что должен вернуть чекер (например, `1` или `OK`)

### Режимы тестирования

#### Обычный режим (`independent_tests: false`)
- Тесты выполняются последовательно
- При первой ошибке тестирование прекращается
- Участник получает баллы только за пройденные тесты до ошибки

#### Независимый режим (`independent_tests: true`)
- Все тесты выполняются независимо
- Даже при ошибке в одном тесте, остальные продолжают проверяться
- Участник получает баллы за все пройденные тесты

## 🔧 Кастомный чекер

Чекер позволяет гибко проверять вывод участника, когда простое сравнение строк не подходит.

### Как добавить чекер

1. В `config.json` задачи установите:
   ```json
   "use_checker": true
   ```

2. В папке `ans/` для каждого теста укажите ожидаемый результат в формате, который понимает чекер

### Как работает чекер

`checker.py` обрабатывает вывод программы участника и преобразует его в нужный формат, после чего сравнивает с содержимым `ans/{i}.txt`.

#### Примеры использования чекера:

**1. Игнорирование пробелов и регистра:**
- Вывод участника: `"  Hello  World  "`
- Чекер приводит к: `"helloworld"`
- В `ans/1.txt`: `"helloworld"`

**2. Проверка с погрешностью (задачи с плавающей точкой):**
- Вывод участника: `"0.33333333"`
- Чекер сравнивает с абсолютной/относительной погрешностью
- В `ans/1.txt`: `"0.333"` (ожидаемое значение)

**3. Сложная валидация формата:**
- Задача: вывести "YES" если число простое, иначе "NO"
- Чекер проверяет корректность ответа
- В `ans/1.txt`: `"YES"` или `"NO"`

**4. Возврат кода ошибки:**
- Чекер может возвращать `0` (принято) или `1` (ошибка)
- В `ans/1.txt`: `"0"`

### Пример реализации чекера

```python
# checker.py
def check_output(output, expected, test_num):
    """
    output: вывод участника (строка)
    expected: ожидаемый результат из ans/{test_num}.txt
    test_num: номер теста
    возвращает: True если тест пройден, иначе False
    """
    # Пример: игнорируем пробелы и переводим в нижний регистр
    normalized_output = ' '.join(output.strip().lower().split())
    normalized_expected = ' '.join(expected.strip().lower().split())
    
    return normalized_output == normalized_expected
```

## 👥 Управление пользователями

Скрипт `admin.py` - основной инструмент для управления участниками.

### Команды

| Команда | Синтаксис | Описание | Пример |
|---------|-----------|----------|---------|
| `add` | `add <user> <password>` | Добавить участника | `python admin.py add ivan 12345` |
| `del` | `del <user>` | Удалить участника | `python admin.py del ivan` |
| `clear` | `clear <user>` | Очистить результаты участника | `python admin.py clear ivan` |
| `delall` | `delall` | Удалить всех участников | `python admin.py delall` |
| `clearall` | `clearall` | Очистить результаты всех участников | `python admin.py clearall` |
| `top` | `top` | Сформировать рейтинг в top.txt | `python admin.py top` |

### Формат базы данных (`users_data.json`)

```json
{
  "ivan": {
    "password": "12345",
    "contest1A": 100,
    "contest1B": 85,
    "contest2A": 100
  },
  "petr": {
    "password": "qwerty",
    "contest1A": 100
  }
}
```

- Ключ задачи: `contest{номер}{буква}` (например, `contest3C`)
- Баллы: от 0 до 100 (1 балл за тест)

## 🔧 API и работа системы

### Процесс проверки решения

1. Участник отправляет решение через веб-форму
2. Файл сохраняется в папку `test/`
3. `checker.py` компилирует/запускает решение
4. Для каждого теста:
   - Программа получает входные данные из `test/{i}.txt`
   - Результат сравнивается с `ans/{i}.txt`
   - Если `use_checker: true`, результат сначала обрабатывается чекером
5. Подсчитывается количество пройденных тестов
6. Баллы сохраняются в `users_data.json`

## ❓ Часто задаваемые вопросы

**Q: Какое минимальное количество контестов и задач можно создать?**  
A: Можно создать 1 контест с 1 задачей. Главное, чтобы нумерация шла по порядку (contest1, задача A).

**Q: Сколько тестов нужно подготовить для задачи?**  
A: Ровно 100 тестов. Это обязательное требование системы.

**Q: Как добавить кастомный чекер?**  
A: Установите `use_checker: true` в `config.json` и реализуйте логику проверки в `checker.py`. В папке `ans/` храните то, что должен вернуть чекер.

**Q: Что такое чекер и зачем он нужен?**  
A: Чекер позволяет гибко проверять вывод программы. Например, игнорировать лишние пробелы, проверять числа с погрешностью или валидировать сложные форматы вывода.

**Q: Как начисляются баллы?**  
A: Каждый пройденный тест дает 1 балл. Максимум 100 баллов за задачу.

**Q: Что происходит при повторной отправке решения?**  
A: Старые баллы перезаписываются новыми, если новое решение показало лучший результат.

**Q: Как сформировать рейтинг участников?**  
A: Выполните команду `docker exec -it tournament python admin.py top`. Рейтинг сохранится в файле `top.txt`.

**Q: Где хранятся отправленные решения?**  
A: Временно в папке `test/`. После проверки они удаляются.

**Q: Как изменить порт запуска?**  
A: В команде `docker run` измените `-p 5000:5000` на нужный порт, например `-p 8080:5000`.

**Q: Нужно ли перезапускать контейнер после добавления новых задач?**  
A: Нет, система автоматически подхватывает изменения в папке `tasks/`.

## 📝 Примечания для администраторов

- Скрипт `generator.py` предназначен для ручного использования администраторами. В нем можно реализовать функции для автоматической генерации тестов
- Все данные хранятся в текстовых файлах, рекомендуется регулярно делать резервные копии папок `tasks/` и файла `users_data.json`
- При добавлении новых задач или контестов сервер не требует перезагрузки
- Для запуска команд внутри Docker-контейнера используйте `docker exec -it tournament <команда>`
- Чекер можно дорабатывать под конкретные задачи, добавляя новую логику проверки в `checker.py`
